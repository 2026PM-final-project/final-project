# 랭킹 기능 및 점수 계산 방식

현재 소스 코드의 동작을 기준으로 정리한 문서입니다. 점수는 한 캠페인 동안 누적되며, **일반 캠페인의 STAGE 3까지 모두 클리어한 결과만** 로컬 랭킹에 반영합니다. 완료한 날짜와 실제 시각을 `YYYY-MM-DD HH:mm:ss` 형식의 24시간제로 기록합니다.

## 1. 행동별 점수

| 행동 | 획득 점수 | 적용 조건 |
|---|---:|---|
| 부서지는 벽 파괴 | +10 | 벽 한 칸을 실제로 파괴했을 때 |
| Fire 아이템 획득 | +50 | 노출된 아이템을 플레이어가 획득했을 때 |
| Bomb 아이템 획득 | +50 | 노출된 아이템을 플레이어가 획득했을 때 |
| Speed 아이템 획득 | +50 | 노출된 아이템을 플레이어가 획득했을 때 |
| 일반 적 `Wanderer` 처치 | +200 | 적의 체력이 0이 되어 사망했을 때 |
| 추격 적 `Chaser` 처치 | +200 | 적의 체력이 0이 되어 사망했을 때 |
| 고속 적 `Swift` 처치 | +200 | 적의 체력이 0이 되어 사망했을 때 |
| 장갑 적 `Armored` 처치 | +400 | 서로 다른 폭발로 두 번 피해를 받아 사망했을 때 |
| 스테이지 클리어 | +1,000~1,600 | 열린 출구에 진입했을 때 |

- 한 벽에 여러 화염이 겹쳐도 벽 파괴 점수는 한 번만 얻습니다. 출구나 아이템이 숨겨진 벽도 파괴 점수는 동일합니다.
- 아이템을 노출시키는 것만으로는 아이템 점수를 얻지 못합니다. 벽을 파괴하고 아이템까지 획득하면 합계 **60점**입니다.
- 장갑 적의 첫 번째 피격에는 점수를 주지 않고, 처치할 때 400점을 줍니다. 이미 죽은 적에게 화염이 계속 닿아도 점수를 중복 지급하지 않습니다.
- 폭탄 설치·기폭 자체와 연쇄폭발 횟수에는 별도 점수가 없습니다. 연쇄폭발로 파괴한 벽과 처치한 적의 점수는 각각 더합니다.

구현: [Game::reveal / Game::resolveContacts](../src/game.cpp).

## 2. 스테이지 클리어 보너스

다음 세 조건을 모두 만족하면 클리어 보너스를 한 번 지급합니다.

1. 스테이지의 적을 모두 처치합니다.
2. 출구를 덮고 있는 벽을 파괴해 출구를 노출합니다.
3. 플레이어가 열린 출구 칸에 진입합니다.

적 전멸과 출구 노출의 순서는 상관없습니다. 적을 모두 처치하기만 해서는 클리어되지 않습니다.

```text
t = 현재 스테이지의 누적 게임 시간(초)
시간 보너스 = max(0, 600 - floor(t) × 2)
클리어 보너스 = 1,000 + 시간 보너스
```

실제 C++ 계산식은 다음과 같습니다. 경과 시간은 음수가 아니므로 `int(stageElapsed)`는 소수점 이하를 버리는 `floor(t)`와 같습니다.

```cpp
score += 1000 + std::max(0, 600 - int(stageElapsed) * 2);
```

| 클리어 시간 | 시간 보너스 | 총 클리어 보너스 |
|---|---:|---:|
| 60초 | 480 | 1,480 |
| 90초 | 420 | 1,420 |
| 120초 | 360 | 1,360 |
| 300초 이상 | 0 | 1,000 |

- 시간 보너스는 정수 초 단위로 2점씩 줄어들며, 0점 아래로 내려가지 않습니다.
- 타이머는 스테이지마다 0부터 다시 시작합니다. 해당 스테이지에서 목숨을 잃어도 타이머는 초기화하지 않습니다.
- 일시정지, 도움말, 랭킹, STAGE 준비 화면에서는 게임 시간이 증가하지 않습니다.
- STAGE 3도 같은 보너스 공식을 적용합니다. 이후 `FINAL STAGE CLEAR!`를 표시하며, 별도의 최종 승리 점수나 남은 목숨 보너스는 없습니다.

## 3. 총점과 계산 예시

```text
총점 = 벽 파괴 수 × 10
     + 아이템 획득 수 × 50
     + 일반·추격·고속 적 처치 수 × 200
     + 장갑 적 처치 수 × 400
     + 클리어한 각 스테이지의 보너스 합계
```

예를 들어 STAGE 1에서 벽 12개를 파괴하고 아이템 3개를 획득한 뒤, 일반 적 2마리와 추격 적 1마리를 처치하고 90초에 출구로 나왔다면 다음과 같습니다.

```text
벽 파괴       12 × 10 =   120
아이템 획득    3 × 50 =   150
적 처치       3 × 200 =   600
클리어 보너스          = 1,420
--------------------------------
합계                  = 2,290점
```

STAGE 2는 이 2,290점을 유지한 상태에서 시작합니다. 이 시점에는 STAGE 1만 완료했으므로 랭킹에 저장하지 않습니다. 목숨을 잃어도 누적 점수는 차감하지 않습니다. 새 캠페인을 시작하면 점수는 0으로 초기화됩니다.

## 4. 랭킹 화면

| 조작·표시 | 동작 |
|---|---|
| `R` 또는 `Tab` | 랭킹 화면 열기 / 닫기 |
| 랭킹 화면에서 `Esc` | 랭킹 닫기 |
| `HIGH SCORES` | 순위, 점수, 완료 스테이지 `S3`, 클리어 날짜·시각 표시 |
| 시각 표시 | 예: `2026-11-26 21:04:09`. 24시간제이며 초까지 표시 |
| 기록이 없을 때 | `Clear STAGE 3 to set a record.` 표시 |
| 랭킹 화면을 보고 있을 때 | 게임 진행과 게임 시간 정지 |

플레이어 이름을 입력하거나 계정에 연결하는 기능은 없습니다. 각 플레이 결과가 하나의 기록이며, 같은 사람이 여러 순위를 차지할 수 있습니다.

화면 상단의 `HIGH SCORE`는 **저장된 최고 점수와 현재 플레이 점수 중 큰 값**입니다. 현재 플레이 점수가 표시되었다고 해서 랭킹에 저장된 것은 아닙니다. 연습 모드의 현재 점수도 이 표시에 반영될 수 있지만 랭킹에는 기록하지 않습니다.

구현: [Application::commands / Application::frozen](../src/main.cpp), [Renderer::retroHud / Renderer::retroOverlay](../src/retro.cpp).

## 5. 랭킹 저장 시점

| 상황 | 랭킹 반영 |
|---|---|
| 일반 캠페인에서 목숨이 0이 되어 `GAME OVER` | STAGE 3까지 도달했어도 저장하지 않음 |
| 일반 캠페인의 STAGE 3 클리어 | 최종 누적 점수와 클리어 날짜·시각을 한 번 기록 |
| STAGE 1 또는 STAGE 2 클리어 | 점수만 누적하고 랭킹 저장은 보류 |
| F3 연습 모드 | 점수 계산은 하지만 랭킹에는 기록하지 않음 |
| 진행 중 `Esc`로 홈 복귀 또는 `F4`로 새 캠페인 시작 | 중간 결과 저장 안 함 |
| 진행 중 게임 창 종료 | 중간 결과 저장 안 함 |

`Application::record()`는 `practice == false`, `stage == 3`, `phase == Victory`를 모두 만족할 때만 저장을 시도합니다. 최종 클리어를 처리한 프레임에서 컴퓨터의 로컬 날짜와 시각을 함께 가져오고, `recorded` 플래그로 같은 결과를 매 프레임 중복 저장하지 않게 합니다.

이 시각은 플레이에 걸린 시간이 아니라 **최종 클리어한 실제 시점**입니다. 예를 들어 오후 9시 4분 9초는 `21:04:09`, 자정은 `00:00:00`으로 기록합니다.

저장에 실패하면 하단 안내에 `Ranking could not be saved. Check folder write permission.`를 표시합니다. 현재 구현은 실패한 경우에도 해당 판에서 자동으로 재시도하지 않습니다.

## 6. 순위 결정 규칙

1. **점수가 높은 기록**을 먼저 배치합니다.
2. 점수가 같으면 **기존 순서**를 유지합니다. 새 기록은 동점인 기존 기록 뒤에 놓입니다.
3. 정렬 후 **상위 10개만** 보관합니다. 10위 밖의 기록은 파일에 남지 않습니다.

모든 기록이 STAGE 3 클리어 결과이므로 스테이지로 순위를 나누지 않습니다. 날짜·시각도 순위 비교에 사용하지 않으며, 동점이나 같은 초에 완료한 별도 플레이 결과를 하나로 합치지 않습니다. 정렬에는 `std::stable_sort`를 사용합니다.

구현: [sortScores](../src/scores.cpp).

## 7. 저장 파일과 읽기·쓰기

### 파일 위치와 형식

랭킹은 **실행 파일과 같은 폴더의 `scores.tsv`**에 저장합니다. 예를 들어 `build/BombermanDemo.exe`를 실행하면 `build/scores.tsv`를 사용합니다. 다른 빌드 폴더의 실행 파일은 그 폴더의 점수 파일을 사용합니다.

헤더 없이 한 줄에 한 기록을 저장하며, 네 필드를 탭으로 구분합니다.

```text
점수<TAB>완료 스테이지<TAB>플레이 인원<TAB>클리어 날짜 시각
```

예시:

```tsv
8290	3	1	2026-11-26 21:04:09
7800	3	1	2026-11-26 23:59:58
```

현재 게임은 1인용이므로 새 기록의 플레이 인원은 항상 `1`입니다. 인원 필드의 읽기 범위는 기존과 같이 `1~2`이며, 완료 스테이지는 반드시 `3`이어야 합니다. 날짜와 시각은 한 번의 시계 조회로 가져와 `YYYY-MM-DD HH:mm:ss`로 함께 저장합니다.

기존의 **날짜만 있는 기록은 랭킹에서 제외**합니다. 과거에는 STAGE 3 게임오버도 저장했으므로, `S3`라는 값만으로 최종 클리어를 증명할 수 없기 때문입니다. 읽기만으로 원본 파일을 수정하지 않으며, 새로운 최종 클리어를 저장할 때 새 조건에 맞는 상위 10개로 파일을 갱신합니다.

### 읽기와 저장 과정

- 프로그램 시작 시와 결과 저장 시도 후에 점수 파일을 읽어 화면용 랭킹을 갱신합니다. 프로그램을 다시 실행해도 기록을 유지합니다.
- 파일이 없으면 빈 랭킹으로 시작합니다. 형식이 잘못된 줄은 건너뜁니다.
- 유효한 기록은 점수 `0~1,000,000,000`, 스테이지 `3`, 인원 `1~2`, 완료 시각 `YYYY-MM-DD HH:mm:ss`를 만족해야 합니다. 시는 `00~23`, 분·초는 `00~59`만 허용합니다. 날짜는 숫자·하이픈 배치를 확인하며 실제 달력상의 날짜까지 검사하지는 않습니다.
- 저장 시 기존 기록과 새 기록을 합쳐 정렬하고 상위 10개를 선택합니다.
- `scores.tsv.tmp`에 내용을 모두 쓰고 flush한 뒤 `scores.tsv`를 교체합니다. Windows에서는 `MoveFileExW`의 교체·쓰기 완료 옵션을 사용합니다.

구현: [RankEntry](../src/scores.hpp), [readScores / saveScore / localTimestamp](../src/scores.cpp), [Application::record / WinMain](../src/main.cpp).
