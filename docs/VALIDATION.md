# 검증 기록

## 시작 안내와 랭킹 종료 키 정리 (2026-11-26)

- 시작 화면은 `USE ARROWS TO MOVE`, `PRESS SPACE BAR FOR A BOMB`, `PRESS R FOR RANKING`, `N/M: SOUND ON/OFF`를 표시한다. Space로 게임을 시작하는 안내는 유지한다.
- 랭킹은 R로 열고 Enter로만 닫는다. 안내도 `PRESS ENTER TO EXIT`로 맞췄다. Tab·Esc·R은 랭킹을 닫지 않으며, N/M 사운드 전환은 랭킹에서도 동작한다.
- 랭킹을 닫는 Enter는 해당 프레임에서 소비한다. STAGE 준비 건너뛰기·다음 스테이지 진행·재시작·폭탄 설치로 같은 입력이 전달되지 않는지 검증했다.
- 기존 기본 임무 안내 문구는 삭제하고, 스테이지 로드 시 notice를 비운다. 시작 화면·랭킹·일반 게임의 실제 렌더링을 확인했다.
- 게임 규칙·데이터 90개와 입력·화면 흐름 23개, 총 113개 테스트가 통과했다. Visual Studio x64 Release 빌드도 성공했다.
- 실행 중인 기존 Debug/GCC 게임은 유지했다. `Run Demo.cmd`는 새 `build-vs/Release/BombermanDemo.exe`를 선택한다. 랭킹 데이터는 수정하지 않았고 복원된 9466점 기록이 유지됨을 확인했다.

## 선택한 기록 복원 및 재실행 유지 (2026-11-26)

- 사용자가 확인한 `9466점 / S3 / 2026-11-26` 한 건을 복원하고 나머지 7건을 제거했다. 원래 시각은 알 수 없으므로 임의의 시·분·초를 만들지 않았다.
- 날짜 전용 복원 기록은 `LEGACY_CONFIRMED` 표시가 있는 경우에만 허용한다. 다른 날짜 전용 구형 기록은 계속 제외하며, 새 최종 클리어 기록은 24시간제 초 단위 timestamp를 사용한다.
- 프로젝트 내 실행 파일들은 공통 `data/scores.tsv`를 사용한다. 프로젝트 밖의 단독 실행 파일은 실행 파일 옆 점수 파일로 동작한다. 복원 기록은 이후 새 기록을 저장해도 보존된다.
- 현재 실행 중인 이전 Debug 바이너리와의 호환을 위해 그 경로의 점수 파일에도 선택한 날짜 전용 기록만 남겼다. 새 버전은 이 별도 파일 대신 공통 저장소를 읽는다.
- 실제 새 실행 파일을 서로 다른 작업 폴더에서 두 번 실행해 랭킹 화면의 복원 기록을 확인했고, 실행 전후 공통 점수 파일이 변경되지 않았음을 확인했다.
- 입력·저장 통합 테스트 21개가 통과했다. 규칙·데이터 테스트는 기존 무작위 맵 검사 T53이 최초 실행에서 한 차례 실패했고, 실패 그룹 재실행에서는 90개 모두 통과했다. 이번 변경에서 맵 생성 로직은 수정하지 않았다.

## speed_changes 랭킹 timestamp 통합 검토 (2026-11-26)

- 확인 시 브랜치 HEAD는 `c8f6da0`이며, 기존 코드는 날짜만 저장하고 게임오버도 기록했다. 아래 수정은 현재 로컬 작업 파일에 반영했다.
- 일반 캠페인의 STAGE 3 최종 클리어만 기록한다. 게임오버·중간 클리어·연습·속도 조정 판은 제외한다.
- 완료 시각은 한 번의 로컬 시계 조회로 `YYYY-MM-DD HH:mm:ss`에 저장한다. 24시간제와 초 단위를 사용하고 같은 결과를 중복 저장하지 않는다.
- 날짜 전용 구형 기록을 제외하며, 날짜·윤년·시각 범위(시 00~23, 분·초 00~59)를 검증한다. 자정과 23:59:59도 저장·읽기를 확인했다.
- 실제 점수 파일의 잘못된 기록은 `build/scores.tsv` 3건, `build-vs/Debug/scores.tsv` 10건, 총 13건을 삭제했다. 두 파일 모두 남길 유효 기록이 없어 파일도 삭제했다. 빌드·테스트 로그는 삭제하지 않았다.
- 게임 규칙·데이터 테스트 88개와 Windows 입력·화면 흐름 테스트 20개, 총 108개가 통과했다. 속도 슬라이더 및 테스트 판 랭킹 제외 회귀도 포함한다.
- `Run Demo.cmd`는 새 `build/BombermanDemo.exe`를 선택한다. 검토 당시 실행 중이던 Debug 게임은 이전 바이너리이므로, 새 저장·표시 규칙은 새 실행 파일로 재실행해야 적용된다.
